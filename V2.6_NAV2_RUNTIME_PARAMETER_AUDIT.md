## 1. Executive Summary

A live ROS 2 parameter audit was performed on the running navigation stack (`autonomous_robot_bringup full_system.launch.py`) to verify whether the parameter changes claimed in the V2.6 final reports were actually received and executed by Nav2.

### Critical Discovery:
In `ros2_ws/src/autonomous_robot_navigation/config/nav2_params.yaml`, the entire `local_costmap` configuration block was **indented 4 spaces inside `controller_server: ros__parameters:`**.

Because Nav2 launches `local_costmap` as an independent ROS 2 node (`/local_costmap/local_costmap`), **Nav2 completely ignored the entire local costmap configuration in `nav2_params.yaml`**. 

As a direct result:
1. `local_costmap` loaded hardcoded C++ defaults:
   - **Inflation Radius:** **`0.55 m`** (Report claimed **`0.30 m`**).
   - **Cost Scaling Factor:** **`10.0`** (Report claimed **`4.5`**).
   - **Robot Radius:** **`0.10 m`** (Config specified **`0.22 m`**).
   - **Rolling Window:** **`False`** (Config specified **`True`**).
   - **Global Frame:** **`map`** (Config specified **`odom`**).
   - **Observation Sources:** **`""` (EMPTY)** (Config specified **`scan semantic_obstacles`**).
2. The local costmap was **not rolling with the robot** and had **no LiDAR or vision observation sources** active.
3. The $0.55\text{ m}$ inflation radius created massive overlapping inflation halos across all $0.85\text{ m}$ doorways ($2 \times 0.55\text{ m} = 1.10\text{ m} > 0.85\text{ m}$), completely blocking doorways and trapping the robot inside rooms such as the Hospital Ward.

## 2. YAML Structure Analysis

### 2.1 Git Diff Evidence (`0ef2f8b` -> `25bab3f`)
In baseline V2.5.0 (`0ef2f8b`), `local_costmap` was defined as a root-level key:
```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      update_frequency: 5.0
      publish_frequency: 2.0
      global_frame: odom
      ...
```

In V2.6 commit `25bab3f`, `local_costmap` was incorrectly moved under `controller_server`:
```yaml
controller_server:
  ros__parameters:
    use_sim_time: True
    ...
    FollowPath:
      plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
      ...
    local_costmap:
      ros__parameters:
        update_frequency: 5.0
        publish_frequency: 2.0
        global_frame: odom
        robot_base_frame: base_footprint
        use_sim_time: True
        rolling_window: true
        width: 6
        height: 6
        resolution: 0.05
        robot_radius: 0.22
        plugins: ["obstacle_layer", "inflation_layer"]
        inflation_layer:
          plugin: "nav2_costmap_2d::InflationLayer"
          cost_scaling_factor: 4.5
          inflation_radius: 0.30
      obstacle_layer:
        plugin: "nav2_costmap_2d::ObstacleLayer"
        ...
```

### 2.2 ROS 2 Parameter Scoping Rule Violation
In ROS 2, YAML parameter files map top-level keys to node names:
- The node spawned by `nav2_controller::ControllerServer` for the local costmap is named `/local_costmap/local_costmap` (node `local_costmap` in namespace `/local_costmap`).
- ROS 2 expects parameter mapping under:
  ```yaml
  local_costmap:
    local_costmap:
      ros__parameters:
  ```
- Because `local_costmap` was nested inside `controller_server: ros__parameters:`, the ROS 2 parameter loader treated `local_costmap` as an unrecognized sub-parameter of `/controller_server`. 
- When `/local_costmap/local_costmap` initialized, it found no matching entries in the YAML file and silently defaulted all parameters.

## 4. Root Cause of Hospital Ward Entrapment & Second-Run Failures

This parameter audit reveals the physical mechanism behind the reported second-run failures:

1. **Global/Local Planner Conflict:**
   - The **global planner** (using `global_costmap` with `inflation_radius = 0.30 m`) successfully calculates a valid collision-free path out of the hospital ward door ($0.85\text{ m}$ doorway width).
   - The **local controller** (using `local_costmap` with default `inflation_radius = 0.55 m`) evaluates the local trajectory against lethal inflated obstacles that cover the entire doorway ($2 \times 0.55 = 1.10\text{ m} > 0.85\text{ m}$).
   - The local controller detects a collision forward, decelerates to zero speed (`FollowPath.regulated_linear_scaling_min_speed = 0.15 m/s` or stops), and aborts.
2. **Missing Local Obstacle Clearing:**
   - Because `obstacle_layer.observation_sources` is empty in `local_costmap`, dynamic obstacles and lidar points are not dynamically cleared or marked in the local rolling frame.
   - Combined with `global_frame: map` and `rolling_window: false`, the local costmap behaves as an un-cleared static grid.

## 5. Summary & Remediation Requirement

1. **Which local costmap parameters Nav2 actually receives:** Only hardcoded C++ defaults.
2. **Which parameters are missing/ignored:** All user-specified local costmap parameters (`inflation_radius`, `cost_scaling_factor`, `robot_radius`, `rolling_window`, `global_frame`, `observation_sources`).
3. **Whether inflation radius is actually 0.30 m:** **NO.** It is `0.55 m` in the local costmap.
4. **Whether cost scaling is actually 4.5:** **NO.** It is `10.0` in the local costmap.
5. **Whether controller parameters are actually loaded:** **YES.** The RPP controller parameters are properly loaded.
6. **Whether runtime matches report claims:** **NO.** The runtime system at commit `25bab3f` is physically incapable of achieving the claimed doorway clearance and transit performance due to the $0.55\text{ m}$ default local inflation radius.
