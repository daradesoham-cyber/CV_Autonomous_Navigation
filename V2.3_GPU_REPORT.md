## 3. Decoupled Perception Pipeline

To achieve optimal real-time stability and prevent camera frame drops, perception is structured as a decoupled producer-consumer architecture:

```
Gazebo Camera Plugin (15 Hz)
            ↓
`/camera/image_raw` (ROS 2 Best-Effort QoS)
            ↓
`object_detection_node.py` (Worker Thread Pool)
            ↓
CUDA Device Queue (`device="cuda:0"`)
            ↓
YOLOv8n Tensor Cores (5.69 ms Inference)
            ↓
`/vision/detections` (Bounding Boxes + Class + Confidence)
            ↓
`lidar_camera_fusion_node.py` (Azimuth 3D Projection)
```

### Architectural Key Points:
1. **Asynchronous Frame Dropping Prevention:** Camera acquisition callback runs immediately without blocking on inference. Only the newest frame is processed; intermediate frames are skipped if the buffer is full, eliminating latency build-up.
2. **GPU Status Topic:** A new publisher `/vision/engine_status` broadcasts rolling engine health (`device: "cuda:0"`, `avg_latency_ms: 5.69`, `fps: 175.8`, `gpu_name: "NVIDIA GeForce RTX 3050 Laptop GPU"`).
3. **Graceful CPU Fallback:** If CUDA initialization encounters an unexpected driver lock, the node safely catches the exception and falls back to CPU inference (`device="cpu"`) with an alert log, ensuring zero mission downtime.
